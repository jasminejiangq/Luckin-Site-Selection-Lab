# Luckin Manhattan expansion — IEOR E4004 Group 36, Milestone 4 code

Competitive facility-location MILP with multinomial-logit customer choice
(Haase & Müller 2014 linearization + lower link (5c) + valid tangent cuts (5d)), cannibalization,
budget, spacing and incumbent-retention constraints. Equation numbers below
match the Milestone 3 report.

## Quick start
```bash
pip install -r requirements.txt
grbgetkey <academic-licence-key>          # once per machine
python tests/test_model.py                # exactness + brute-force checks -> ALL TESTS PASSED
python src/synthetic.py                   # synthetic test instance -> data/synthetic/
python src/run.py --data synthetic --solver gurobi --time-limit 120
```

## Real instance (Milestone 4)
```bash
python src/fetch_data.py                  # step 1: download + clean public inputs
python src/build_instance.py --walk grid  # step 2: freeze five model tables
python src/run.py --data real --solver highs --scenario all --time-limit 600    # step 3
python src/visualize_results.py           # step 4: figures from solver output
python src/generate_report.py              # step 5: Milestone 4 report
```
Outputs: `outputs/real/MILESTONE4_REPORT.md`, `summary.json`,
`plan_<scenario>.csv`, `cross_scenario.csv` (regret), and the explanatory PNGs in
`outputs/real/figures/`.
The full formulation is in `src/model_highs.py` and `src/model_gurobi.py`.
HiGHS is used for the real-data instance because the academic Gurobi license commonly
caps model size below this instance; the tiny regression tests cross-check both
implementations against exhaustive enumeration.

### Data sources, vintages, and cleaning
`data/raw/source_manifest.json` records retrieval time, source URLs/queries, and row counts.
Downloaded source files, cleaned inputs, and SHA-256 hashes are kept in `data/raw/`;
the five model-ready tables and their build manifest are kept in `data/processed/`.

| Input | Source / vintage | Cleaning and interpretation |
|---|---|---|
| Tract geography | Census 2024 Gazetteer | New York County GEOIDs (`36061`); internal representative points |
| Residents | Census 2024 ACS 5-year, B01003 | Parsed from the Census Bureau's table-based bulk file; estimates and margins of error retained. ACS API access now requires a key, so the script does not depend on one. |
| Jobs | LEHD LODES 8, NY WAC JT01, 2023 | Block-level primary jobs (`C000`) summed to 11-digit tract GEOIDs; unlisted tracts are zero after the join. |
| Transit | MTA Subway Hourly Ridership, August 2026 | Summed by station complex/day, then averaged over observed days; each station complex is assigned to its nearest tract representative point once. |
| Competitors / incumbents | NYC DOHMH Restaurant Inspection Results (`43nn-pn8j`) | Manhattan coffee/tea establishments and named chains; deduplicated by CAMIS and latest inspection/update. This source does not prove a business is currently open. |
| Candidate sites | NYC DOF Storefronts Reported Vacant or Not (`92iy-9c3n`), reporting year 2025 | Use the latest positive vacancy report (`vacant_6_30_or_date_sold=YES`), or year-end vacancy when no later status was reported; exclude reported construction, invalid Manhattan coordinates, and duplicate geocoded points. The resulting set is sourced, not forced to 900. |

Important limitations: DOF coordinates are at storefront/building level and do not identify
an entrance; rent and reusable fit-out are not supplied by that dataset. The existing
$9/sf/month rent fallback and fit-out flag are assumptions, not measured rents or property
attributes. The Luckin list generated by `fetch_data.py` is a provisional list of
unique DOHMH records, not an independently verified open-store list. Confirm it against a
current official Luckin source and replace `data/raw/luckin.csv` before reporting results.
Likewise, competitor inspection records are location proxies, not verified operating-status
records. The default `--walk grid` produces a rotated-grid distance approximation, not
pedestrian-network distances; disclose that assumption or build with `--walk osmnx`.

## Files → report
| file | report element |
|---|---|
| `src/config.py` | every parameter, tagged D / A / E |
| `src/params.py` | eq. (1) demand index, (2) λ and w, (3) attraction and γ, (6) Φ, sets E and N |
| `src/model_gurobi.py` | eq. (5a)–(5d), (7)–(13) — one block per equation |
| `src/model_highs.py` | same MILP as sparse matrices, solved by HiGHS (licence-free cross-check) |
| `src/evaluate.py` | closed-form logit evaluation (4) of any plan, constraint checks, greedy heuristic |
| `src/run.py` | scenarios low/base/high, sanity assertions, cross-scenario regret |
| `tests/test_model.py` | validation promised in M3 §5 |

## Sanity checks run automatically by `run.py`
* solver objective == NPV recomputed from the closed-form shares (4)
* plan satisfies (8)–(12)
* MILP ≥ greedy plan (greedy is also the MIP start)
* `evaluate()` asserts the identity bracket = (1−γ)(1−P0) and Z(no openings) = 0

## Notes
* `--walk grid` uses L1 distance on the 29°-rotated Manhattan grid as a stand-in for pedestrian routes; state this as an assumption or use `--walk osmnx`.
* λ is computed with the BASE choice parameters, so market scale w stays frozen when β, u0 or D_max are varied (M3 §1).
* `tests/fake_gurobipy/` is a test-only stand-in that runs `model_gurobi.py` on HiGHS; never use it for reported results.
* Synthetic data are invented and must never be reported as Manhattan results.
* (5d) tangent cuts: 1−P_i0 = S/(U+S) is concave in S = Σ V x, so tangents are valid upper bounds. They cut off no integer plan
  (test [1b]) but shrink the synthetic LP bound from $46.2M to $35.3M (best plan $34.9M); HiGHS then proves optimality in 10–31 s.
  Switch off with `tangent_S0 = ()` in config.py.
